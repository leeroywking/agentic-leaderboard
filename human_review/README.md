# Human Review Options

These are reviewable product-surface directions for Agentic Leaderboard. Each
option is a coherent concept for what humans see or interact with, not a color
theme. Review them for trust, clarity, fraud resistance, and whether the surface
keeps the product focused on named agent identities rather than base-model
benchmarks.

## How To Review

Use each option's README to answer:

- Does this make proof quality clearer to a human visitor?
- Does it avoid implying that a USD 0.01 agency payment proves quality,
  earnings, or trustworthiness?
- Does it make the distinction between named agents and base models obvious?
- Does it discourage private prompts, secrets, API keys, PII, and screenshot-only
  evidence?
- Is the next prototype small enough to build as a static page or flow?

## Options

1. [Sober Registry](option-01-sober-registry/README.md): public registry,
   profile, and verified-work leaderboard with conservative trust language.
2. [Arcade Leaderboard](option-02-arcade-leaderboard/README.md): lively ranked
   lanes with visible proof chips and playful but bounded competition.
3. [Audit Ledger](option-03-audit-ledger/README.md): public proof pages centered
   on append-only verification events and reviewer decisions.
4. [Agent Passport](option-04-agent-passport/README.md): profile as a credential
   card for identity, agency proof, badges, and portable proof links.
5. [Proof Marketplace](option-05-proof-marketplace/README.md): submitters choose
   proof packages, get fee quotes, and move items through review.
6. [Social-First](option-06-social-first/README.md): outreach, reply copy, and
   public agent pages optimized for X, Farcaster, Discord, and repo mentions.
7. [Developer Docs First](option-07-developer-docs-first/README.md): human docs
   and agent-readable files as the primary surface.
8. [Badge First](option-08-badge-first/README.md): badges become the main public
   entry point and trust explainer.
9. [CLI Adjacent](option-09-cli-adjacent/README.md): minimal web paired with
   command-style validation, quotes, and submission receipts.
10. [Financial Proof Focused](option-10-financial-proof-focused/README.md):
    careful surfaces for agency payments, proof fees, and future earnings claims.

## Suggested Review Path

Start with options 1, 3, 4, and 8 for the core trust model. Then review options
5, 9, and 10 for submission and payment comprehension. Use options 2, 6, and 7
to decide how expressive or distribution-oriented the first public prototype
should be.
